# 例程 05：双通道滤波记录仪与回差声光报警

这个实验把两路 ADC 变成一个可观察、可修改的记录系统：采集电压，做 32 点滑动均值，在 OLED 上显示两路带一位小数的 mV 数值和独立历史折线；越过上限后，红灯与 PWM 蜂鸣器报警。串口同步输出 CSV，便于核对屏显或导出后分析。

它适合在 AliceSIM 这个嵌入式仿真学习平台里练习“改变输入 → 观察响应 → 修改代码 → 再验证”，不是预设读数的播放动画。原来的基础双路 ADC 工程仍保留，本工程是独立的进阶练习。

## 打开与操作

1. 选择“项目 → 打开工程文件夹”，导入完整 `Learning05_Logger` 文件夹；`.ioc`、源代码和同名 `.alice-sch.json` 电路应一起出现。也可以直接打开例程包中的 `Learning05_Logger.alice.json`。
2. 构建并运行。开关默认闭合，正常状态应为绿灯亮、红灯灭、蜂鸣器关闭。静态输入 A 为 1.1 V、B 为 2.2 V，OLED 显示 `1100.0 mV` 和 `2200.0 mV`。
3. OLED 顶部两行分别为 A、B 的滤波值；下面两幅图分别记录 A、B。每幅图的纵轴都是 0～3300 mV，基线表示 0 V，虚线是约 2500 mV 的参考线；最新值在右侧。最多保留 32 个历史点，不随仿真 tick 无限增长。
4. 把 A 输入从 1.1 V 改成 3.1 V。数值与曲线会逐步上升，滤波值达到 2500.0 mV 后红灯亮、绿灯灭，蜂鸣器显示 2 kHz PWM 工作状态，屏幕写出 `ALARM`。
5. 把 A 降到 2.4 V，报警应继续保持。再降到 2.2 V，并确认 B 也低于 2300.0 mV，报警才解除。这就是回差，能减少阈值附近反复跳变。两路中的任一路都能触发报警。
6. 断开 `SW_RUN`，停止采样，OLED 显示 `READY`，红灯作为待机指示亮起，蜂鸣器关闭。重新闭合会清空滤波窗口和历史曲线，开始新一轮记录，避免把上一次测量混进新记录。
7. 打开虚拟串口，选择 USART2，115200 / 8N1。CSV 列为 `tick_ms,a_mV,b_mV,alarm,state`，状态有 `RUN`、`ALARM`、`READY`、`ADC_ERROR`。待机只发送一次状态记录，不持续刷屏。

完整 `.alice.json` 教学工程包额外预置了 **8 秒循环输入包络**，运行后会真实改变 A/B 的模拟源，方便观察升降、滤波和报警全过程。直接导入源码文件夹时仍使用静态 1.1/2.2 V。想自己调整电压时，在仿真设置切换到无限模式，停止包络覆盖，再编辑模拟源属性。

## 配置与接线

| 模块 | 配置与引脚 | 学习重点 |
|---|---|---|
| STM32F103C8T6 | HSE 8 MHz，PLL ×9，SYSCLK 72 MHz | 时钟、总线分频与外设定时一致 |
| 输入 A | PA0 / ADC1_IN0，12 位，软件启动 | 采样返回状态、指针传出结果 |
| 输入 B | PB0 / ADC2_IN8，12 位，软件启动 | 两路独立输入与统一处理 |
| 运行开关 | PA1，10 kΩ 上拉，开关闭合接地 | 低有效输入，采集/待机状态机 |
| 绿灯 | PB12 → 330 Ω → 绿 LED → GND | 独立输出：正常采集亮 |
| 红灯 | PB13 → 330 Ω → 红 LED → GND | 独立输出：报警或待机亮 |
| SSD1306 OLED | PB6 SCL、PB7 SDA，I²C1 400 kHz，7 位地址 0x3C；各有 4.7 kΩ 上拉 | 帧缓冲、数字与真实历史折线 |
| PWM 蜂鸣器模块 | PA8 / TIM1_CH1；PSC=71，ARR=499，CCR1=250 | 72 MHz / 72 / 500 = 2 kHz，50% 占空比；报警启停 |
| 虚拟串口 | USART2 PA2 TX / PA3 RX，115200 / 8N1 | 带时间戳的 CSV 记录 |
| 电源 | MCU、屏幕、PWM 蜂鸣器模块共 3.3 V / GND | 正确供电、共地与信号连接 |

电路中的蜂鸣器是 **带 VCC/GND/SIG 的 PWM 模块**；接实物时按模块规格供电，裸蜂鸣器或大电流负载应使用合适的驱动电路。STM32 的外部 8 MHz 晶振与去耦属于开发板硬件；本图使用 MCU 抽象符号，真实搭建可采用带晶振的 STM32F103 开发板。

## 代码怎么读

先看 `ReadPair`：检查两次 ADC 启动与等待的返回值，通过指针把成功结果写回调用者；两路都成功才更新滤波，失败会显示 `ADC READ ERROR` 并输出 `ADC_ERROR`，不会把旧值当作新样本。

再看 `AddSample`：两个 32 项环形数组保存最近的原始值；移除将被覆盖的样本、加上新样本，就能在固定开销内更新累加和。窗口未填满时除以实际样本数，启动时不会被 31 个零拉低。换算使用 64 位中间乘积，避免 32 个满量程样本换算到 0.1 mV 时溢出；存储值 `33000` 代表 `3300.0 mV`。

`DrawRecord` 每次把当前滤波值加入有界历史；`DrawTrend` 用 4 像素间距连接实际历史点。它调用随工程提供的 SSD1306 `DrawPixel`、`DrawHorizontalLine` 与 `Update`，源码在实机上也按相同算法绘图。上下两条图分别绘制，单位和量程一致，没有用一条曲线代表两路数据。

主循环使用无符号 tick 差判断采样与刷新是否到期。标称采样任务间隔 20 ms，屏显和 CSV 间隔 100 ms；32 点均值的名义窗口为 640 ms，32 个历史点的首末跨度约 3.1 秒。阻塞 I²C 屏幕传输、UART 与实际 HAL 执行时间会使实机采样间隔变长，所以这些值是软件任务设置，不能当成精密硬件定时采样结果。本例两路依次软件触发，也不是严格同时采样；需要稳定采样率或精确同步时，可继续研究定时器触发与 DMA，例程 04 可作为起点。

报警使用滤波值：任一路达到上阈值置位，只有两路都回落到下阈值以下才复位。上阈值大于下阈值，在回差区间保持原状态。开关控制采集会话；待机红灯与报警红灯共用红色状态指示，屏幕和 CSV 区分原因，两个 LED 始终由两个独立 GPIO 控制。

## 自己改一改

- 把滤波长度从 32 改为 8，再做同样的电压阶跃，比较响应速度和抗波动效果。同步修改测试中对 32 点的预期。
- 调整上下报警阈值，依次试刚低于、刚等于、刚高于阈值的电压，检查回差是否仍有效。
- 给两路设置不同包络，观察一条上升、一条下降时屏幕与 CSV 是否对应。
- 增加峰值、谷值或超限持续时间；先定义停止和重开时应不应该清零，再修改代码。
- 把串口 CSV 保存后画时间电压图，与 OLED 的短历史窗口对照。
- 尝试把 100 ms 屏显改为 200 ms，观察通信开销、历史跨度与界面响应之间的关系。

## 验证与边界

在仓库根目录执行 `node tutorials/examples/Learning05_Logger/verify.cjs`，会构建真实源码模型并加载保存的电路，验证双通道读取、滤波阶跃、两幅 OLED 图、上下回差、独立 LED、2 kHz PWM、满量程、待机与重新开始。执行 `python tutorials/examples/Learning05_Logger/verify.py --clang` 可检查全部 C 源文件的语法与头文件。

工程包含 STM32 HAL / CMSIS 及其许可证、实际 SSD1306 驱动。编译宏为 `USE_HAL_DRIVER`、`STM32F103xB`；头文件路径为 `Core/Inc`、`Drivers/AliceSIM/Inc`、`Drivers/STM32F1xx_HAL_Driver/Inc`、`Drivers/CMSIS/Include`、`Drivers/CMSIS/Device/ST/STM32F1xx/Include`。

AliceSIM 用外设语义与接线模型帮助验证嵌入式程序逻辑。ADC 量化和数字滤波有实际计算，但输入噪声、参考电压漂移、I²C 边沿、蜂鸣器声压与真实处理器指令耗时，需要数据手册和实机实验核对。


## 教程内副本与开发复验

本目录由 `scripts/sync-tutorial-examples.mjs` 从原例程同步。固件、IOC、库与许可证保持原样；开发辅助脚本会向上寻找 AliceSIM 平台根目录。上文复验命令请在 AliceSIM 仓库根目录执行。

独立下载 ZIP 可以直接导入同名 `.alice.json`，正常学习不依赖 Node.js 或这些复验脚本。若要离线做开发复验，请把完整工程目录放入配套平台源码的 `tutorials/examples/` 后执行；也可设置 `ALICESIM_ROOT` 指向平台源码根、`ALICESIM_PYTHON` 指向 Python 3.10+。Clang 复验还需先完成平台依赖准备。
