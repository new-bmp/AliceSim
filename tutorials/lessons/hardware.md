# 把程序放到真实开发板

## 本课准备什么

使用 Learning07_Blink 的 PB12 闪灯程序作为迁移目标。它采用内部 HSI 8 MHz，不依赖外接晶振。目标是先在 AliceSIM 验证分支和接线，再用 STM32CubeIDE、ST-Link 和真实 STM32F103C8T6 开发板完成下载与调试。

需要 STM32F103C8T6 开发板、兼容的 ST-Link 调试器、限流电阻、LED、连接线和数据 USB 线。F103C8 标称 Flash 为 64 KB、SRAM 为 20 KB；不要按一些非官方板子声称的扩容值配置工程。先核对板卡丝印、原理图和芯片料号。

下载 [STM32CubeIDE](https://www.st.com/en/development-tools/stm32cubeide.html)，按系统安装其驱动。CubeMX 中配置引脚，CubeIDE 中编译和调试；AliceSIM 中的“构建”不会替你生成可下载的 ELF，也没有代替 ST-Link 的实机断点功能。

## 先分清手中的几份资料

在 [STM32F103C8 产品页](https://www.st.com/en/microcontrollers-microprocessors/stm32f103c8.html) 下载与料号匹配的资料。先确认芯片与封装，再查引脚和电气限制；读 HAL 函数声明只能知道软件参数，不能代替芯片规格。

| 资料 | 用它回答什么问题 |
| --- | --- |
| Datasheet 数据手册 | 供电范围、引脚排列、5 V 容忍条件、输入阈值、GPIO 电流与存储容量 |
| RM0008 参考手册 | RCC 时钟树、GPIO 模式、定时器、ADC、UART、I²C、SPI 的寄存器与工作流程 |
| PM0056 编程手册 | Cortex-M3 中断、异常与内核相关操作 |
| 板卡原理图、模块说明 | 电源针脚接到哪里、板载电阻/晶振/稳压器、LED 是否低有效 |
| HAL 头文件与实现 | 函数参数、状态值、句柄和回调如何使用 |

练习时请写出资料名称和表格或章节名。例如“这个引脚能否接 5 V”应查数据手册中的引脚类型及电气条件，不能只看模块卖家写的“兼容 STM32”。总线手册的读法继续见 [I²C](i2c-basics.md) 和 [SPI](spi-basics.md)。

## 在 CubeMX 中生成实机工程

1. 新建或打开与本课对应的 STM32F103C8T6 IOC。在 System Core → SYS 中选择 Debug = Serial Wire，保留 PA13、PA14。
2. PB12 设为 GPIO_Output、Push Pull、Low Speed，初始 Low。不使用板载 PC13 灯代替本课接线。
3. 在时钟树选择 HSI 8 MHz 作为 SYSCLK，不启用 PLL；AHB、APB1、APB2 均不分频。用内部时钟做入门实验，频率精度仍以器件规格为准。
4. Project Manager → Toolchain / IDE 选择 STM32CubeIDE，再生成工程。
5. 在 CubeIDE 导入生成的工程，在 USER CODE 区域加入翻转 PB12 与 500 ms 延时的实验逻辑。保留 CubeMX 生成的时钟初始化、HAL 初始化及 SysTick 中断处理。

教材工程把初始化集中在 `main.c`，便于在 AliceSIM 阅读。实机工程由 CubeMX 补齐启动文件、链接脚本与 IDE 配置；不要只复制教材的 `main.c` 覆盖生成的全部文件，也不要再定义第二个 `SysTick_Handler()`。逐项核对配置与业务逻辑即可。

## 断电接线与供电

PB12 → 330 Ω 电阻 → LED 阳极，LED 阴极 → GND。3.3 V 逻辑下绿色 LED 的电流取决于正向压降，按数据手册估算并检查 GPIO 电流限制。初学时不要把负载或电机直接接到 GPIO。

| 调试器信号 | STM32F103C8T6 目标端 | 说明 |
| --- | --- | --- |
| SWDIO | PA13 | 双向调试数据 |
| SWCLK | PA14 | 调试时钟 |
| GND | GND | 目标板与调试器共地 |
| VTref / Target VCC | 目标板 3.3 V 参考 | 按调试器手册确认，它通常用于检测目标电平 |
| NRST | NRST | 可选；连接失败时有助于复位下连接 |

有的探针提供电源，有的只检测目标电压。先读探针说明，再决定目标板由谁供电；不要把两个电源输出直接并联。开发板 USB、电源针脚和稳压器的连接方式也应以该板原理图为准。所有接线在断电时完成。

## 编译、下载与运行

在 CubeIDE 执行 Build，确认没有编译和链接错误，生成目标 ELF。然后建立 STM32 C/C++ Application 调试配置，选择 ST-Link、SWD 接口和对应 ELF，连接目标板后启动 Debug。

调试器可能先停在 `main()`。按 Resume 后程序才持续执行，此时观察 LED。再次下载前确认连接的是自己的实验板，重新写入会替换板上的原程序。

如果找不到目标，先检查目标板电压、共地、PA13/PA14 接线和调试器驱动；降低 SWD 频率再试。若固件很快改动调试引脚或关闭调试，可尝试 Connect under reset，并接好 NRST。不要用反复修改时钟代码代替供电与接线检查。

## 用断点解释一次闪灯

在 `HAL_GPIO_TogglePin()` 调用处下断点，启动调试。观察调用前后的 PB12 输出状态，使用 Step Over 跨过函数，再查看 `HAL_GetTick()` 或局部变量。变量值要结合当前暂停位置理解。

把断点放在延时前后，比较两次命中。暂停时 CPU 停止执行，外设是否继续计数取决于调试冻结设置；调试器也会改变你观察到的时间关系。因此不要用单步操作测量毫秒精度或中断延迟。

循环已通过而变量看不到时，检查编译优化设置和变量作用域。需要观察的变量可能被优化或暂存在寄存器里；使用适合调试的构建配置，再重新构建下载。

## 从闪灯迁移到更多模块

先把 [电路与电平基础](electrical.md) 的电压、电流和共地要求落实到实物，再迁移 ADC、I²C 和 SPI。模拟输入不能超出器件允许范围；HC-SR04 等模块可能输出 5 V 信号，应按具体型号评估分压或电平转换。模块外观相似不代表电气参数相同。

最后记录一次“仿真预期 → 实机观察 → 差异原因”：例如内部时钟误差、按键机械抖动、LED 正向压降和供电噪声。仿真用于理解程序和设备交互，电源裕量、波形边沿、负载和干扰需要数据手册与实测支持。
