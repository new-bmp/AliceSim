# AliceSIM 支持更多 MCU 的可行性

## 结论

支持“一个工程选择不同 STM32 MCU 型号”在架构上可行，当前 IOC 解析、动态引脚布局和大部分 HAL 调用模型都可以复用。建议先扩展同系列、同 HAL 后端的 STM32F1 型号，再逐步加入 F4、G0 等系列。

“同一张原理图同时运行多个 MCU 实例”是另一项更大的功能，需要多运行时调度、固件绑定和跨 MCU 网络同步，不应与多型号支持混为第一阶段。

## 当前已有的可复用部分

- IOC 查看器已经从 `Mcu.CPN`、`Mcu.Name`、引脚 Signal 和时钟字段读取工程配置。
- 原理图 MCU 高度和已启用引脚可以根据 IOC 动态生成。
- GPIO、UART、I²C、ADC 的固件摘要采用相对通用的 HAL 操作描述。
- 工程文件导入可以收集源码、头文件、编译宏和包含目录。

## 当前与 STM32F103C8T6 的耦合

1. 原理图固件验证会拒绝非 STM32F103C8 型号。
2. MCU 定义是全局单例，标题、Blue Pill 图片、电源脚和默认引脚写死。
3. 构建回退宏固定为 `STM32F103xB`。
4. 工程导入只会根据 F103 IOC 自动补充芯片宏。
5. 默认工程、提示文字、示例代码和器件徽标固定为 F103C8T6。
6. 当前兼容头文件和虚拟外设后端主要覆盖 STM32F1 HAL 行为。

## 推荐架构

新增 MCU Profile 注册表，每个型号或兼容型号组提供：

- 型号匹配规则、显示名称、系列和封装；
- 编译宏、HAL 后端和兼容头文件集合；
- 电源脚、引脚命名规则、时钟范围和外设能力；
- 原理图尺寸、平面素材和默认演示连接；
- GPIO、UART、I²C、ADC、定时器等能力声明。

IOC 导入后先解析 Profile，再把 Profile 分别交给工程构建器、原理图和运行时，避免各模块自行判断型号字符串。

## 建议实施阶段

### 阶段 1：F103 兼容型号

支持 STM32F103C8T6、CBT6、RBT6 等共享 F1 HAL 后端的型号。主要工作是解除字符串、封装和引脚数量硬编码，风险较低。

### 阶段 2：第二个 STM32 系列

建议选择 STM32F401CCU6 或 STM32G0 系列，验证 Profile、构建宏、时钟树和 HAL 后端确实能够按系列切换。

### 阶段 3：外设差异

补充系列特有的定时器、DMA、中断、ADC 分辨率、GPIO 复用和时钟规则，并按 Profile 控制可用功能。

### 阶段 4：同图多 MCU

为每个 MCU 绑定独立固件和运行时，在统一仿真时间戳下轮转执行，并通过原理图网络交换 GPIO、UART、SPI 和 I²C 状态。此阶段需要修改电路文件格式和调试界面。

## 验收标准

- 导入非 F103 IOC 后不会错误套用 F103 宏或 Blue Pill 外观。
- 不支持的外设按能力表给出明确诊断，而不是静默模拟。
- 每个 Profile 都有 IOC、构建、引脚、电路保存和 HAL 运行测试。
- 旧的 STM32F103C8T6 工程和电路文件保持兼容。
